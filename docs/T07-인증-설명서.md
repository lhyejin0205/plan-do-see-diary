## 1. 무엇을 막으려 했나 (위협과 목표)

- T06 다이어리는 로그인이 없어 링크를 아는 누구나 기록을 보고 고칠 수 있었다.
- 목표: **가입한 사람마다 자기 기록만** 읽고 쓰게 한다. 로그인하지 않은 사람과 다른 계정은 화면뿐 아니라 **서버에서** 거절된다.
- 막는 대상: 로그인하지 않은 요청, 다른 계정의 기록 읽기·고치기·지우기, 다른 사람 이름(owner_id)으로 기록 넣기.

## 2. 사용한 인증 방식과 선택 이유

- **Supabase Auth, 이메일 + 비밀번호.**
- 이유: T06에서 이미 Supabase DB를 쓰고 있어서, 같은 서비스의 인증을 붙이면 로그인한 사람의 id(`auth.uid()`)를 DB 정책에서 바로 쓸 수 있다. 별도 서버 없이 정적 사이트(Vercel)로 유지된다.
- 비밀번호는 Supabase가 해시로 저장하며 앱 코드나 DB 표에 남지 않는다.
- (채울 것: 이메일 확인을 켰는지/껐는지와 그 이유)
